# BetterSkillManager（`better-skill-manager`）

[English](README.md)

一个持久化的 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) Web 插件：在输入框权限按钮旁添加 **技能** 按钮，把当前会话的技能目录变成可搜索、可筛选、可管理的面板。

**状态：** `1.2.0` 预览版。在 Windows 上针对 DeepSeek Harness `0.2.2-rc.1` 做了 Host 辅助函数测试和 Client 渲染/流程测试；还不是完整的浏览器端到端测试。

借助DeepSeek-V4.1-flash与GPT-6.1-Sol开发。

## 功能

### 浏览与使用

- 技能按钮位于输入框工具条，紧跟在权限/计划控件之后。
- 两个标签页：**当前工作区会话** 与 **用户级**。
- 主标签 **内置 / 用户 / 会话** 单选；选中后只展开该主标签下的子标签，**全部** 取消子标签，**清除筛选** 同时清除主/子筛选。
- 搜索匹配名称、描述、`whenToUse` 和标签。
- 技能行是圆角卡片，悬停轻微放大；点击行会把 `/技能名 ` 插入输入框，走原生技能调用链路；**查看** 在右侧栏打开 `SKILL.md`。
- **来源标记**：通过本插件创建/导入的技能，frontmatter 带 `managed-by: skill-hub`；在面板之外加入的技能（手写文件、`git`、其他工具或代理）会自动获得 **其他途径来源** 子标签。
- 标签保存在技能自己的 `SKILL.md` frontmatter 中（`tags: ["..."]`）。

### 添加与导入

标题栏 **添加** 按钮打开导入表单：

- **名称**
- **标签**
- **作用范围**：当前工作区会话 / 用户级
- **Skill 文件**：拖入 `SKILL.md` 或技能文件夹、从硬盘选择 `.md`，或粘贴 raw 文件 / GitHub / Gitee 地址。

提示文案：

> 可以是拖入也可以从硬盘选择，也可以GitHub，gitee这种开源平台的skill的所在地址

支持的地址：raw `.md`、`github.com/.../blob/...`、`github.com/.../tree/...`、仓库根地址，以及 Gitee 的对应形式。Host 会解析成 raw 文件、抓取内容、同步 frontmatter 名称与标签，然后写入所选作用范围。

地址导入只允许公网 HTTP(S)：IPv4/IPv6 私网、回环、链路本地、IPv4 映射地址、带凭据的地址，以及解析到内网的主机都会被拒绝。组合的 `web` 服务返回的策略错误（重定向、跨源、超限、取消）是最终结果；只有不存在 `web` 服务时才使用原生 fetch，且会手动逐跳跟随重定向、逐跳检查地址并限制字节数。

### 编辑与移动

编辑器分四个模块：

1. **名称**：重命名技能目录/扁平文件，并同步 frontmatter 的 `name`。
2. **标签**：增删 `#标签`，已有标签作为快捷建议。
3. **作用范围**：在 **当前工作区会话**（`<projectRoot>/.dsh/skills` 或 `<projectRoot>/.agents/skills`，同一工作区的会话共享）与 **用户级**（`<dshHome>/skills` 或 `<dshAgentsHome>/skills`，本机所有会话可用）之间移动。
4. **文件内容**：完整 `SKILL.md`，含 frontmatter。

编辑会保留文件当前所在的存储根：`~/.agents/skills` 里的技能不会因为改了标签就被搬到 `~/.dsh/skills`；只有明确改作用范围才会移动。如果打开后文件在磁盘上被外部修改，保存会被拒绝并提示冲突。编辑器用 `workspaceFiles.readBytes` 的原始字节计算哈希，所以 LF/CRLF 和末尾换行差异不会造成误报冲突。

移动会保留 `references/`、`scripts/` 等资源；删除会移除整个技能包。

### 安全说明

- **读取失败不能保存**：编辑器显示“重新读取”和取消，没有保存按钮；Host 也会独立校验 frontmatter 的 `name`/`description`，拒绝空内容。
- **替换失败不会删除原文件**：更新先写临时同目录文件，再 rename 覆盖目标；Windows 瞬时占用会做有界重试。如果最终仍失败，原文件保留、保存报错。独占创建使用 `wx`，外部刚创建的目标不会被覆盖。移动会尽量回滚；没有 WAL、撤销或跨设备事务。
- **YAML 使用保守子集校验**：未闭合引号、未平衡的流式括号、制表符缩进会在写入前拒绝；标签多行数组未修改时原样保留，修改时整块替换；块标量 description 保留；块标量 `name` 或 `tags` 的重写会被拒绝。这不是完整 YAML 解析器，子集之外的合法结构会被拒绝而不是被改写。
- **地址导入只做预检**：插件在抓取每个候选前拒绝私网/解析到私网的地址，组合 `web` 服务的策略错误是最终结果。实际连接由该服务自己的传输策略解析和建立，因此“检查后到连接前”的 DNS 重绑定不由本插件阻止；部署的网络隔离仍是边界。
- **导入标签默认保留**：如果没动标签模块，Host 会保留源文档里的标签（包括它自己抓取的 URL 导入）；在表单里清空全部标签才会发送显式空数组。
- **写入成功与目录未更新分开报告**：有界轮询仍未观察到写入时，面板会提示“文件已写入，目录尚未更新”，并保留 **刷新**。
- **未知 provider 根只读**：Host 只发布用户级与项目级根，其他 provider 或插件根里的技能按“内置”处理。
- **读取失败是来源未知，不是“其他途径来源”**：只有在成功读取头部、确认没有 `managed-by` 标记后，才追加派生来源标签。

## 安装

要求：

- DSH Web/Desktop 配置，包含输入框与 `skills` 服务（自带的 `desktop` / `web` 配置已包含）。
- 无需构建：插件是普通 ES Module + 预构建的 Client bundle。

安装步骤：

1. 克隆或下载本仓库。
2. 在 DSH 中打开 **插件**（Plugin Manager）安装这个本地文件夹，或让 Agent 用 `plugin_manager` 的 `install_bundle` 指向该目录。
3. 确认 `better-skill-manager` bundle 已启用；它的行 id 是 `better-skill-manager`。

`package.json` 带 `"private": true` 是为了避免误发布到 npm；如要发布到你自己的 npm scope/名称，删掉该字段即可。

## 使用

1. 打开任意会话，点击权限按钮旁的 **技能**。
2. 先选主标签，再选子标签，或使用搜索框。
3. 点击技能行把 `/技能名 ` 插入输入框，或点 **查看** 检查 `SKILL.md`。
4. 用 **添加** 导入技能，用 **编辑** 改名、改标签、移动作用范围或修改文件内容。

## 实现

- Client 半部分（`client.js`）注册到 `conversation.input.left`，通过 `ctx.remote.skills.list({ sessionId })` 读取会话目录，用 `workspaceFiles.read` 读取可编辑技能的前 200 行以解析标签与来源，用 `inputActions` 插入 `/name`，用 `ctx.sidebarRight.openResource(...)` 打开文件。它通过 Host 的 `roots` 操作获取可见根，而不是从路径字符串猜测。
- Host 半部分（`index.js`）注册 `/skill-hub` 命令（`recordInput: false`），提供 `roots`、`create`、`import`、`save`、`delete`；只接受根级扁平 Markdown 或直接子目录里的 `SKILL.md`，校验真实文件（拒绝符号链接），串行化写入；更新通过临时同目录文件替换，新建使用 `wx` 独占创建。保存可以携带加载时的内容哈希，不匹配就按外部修改拒绝。
- 地址导入在写入队列之外抓取；只接受公网 HTTP(S)；组合 `web` 服务的策略错误是最终结果，只有该服务不存在时才使用原生回退。
- 面板采用固定高度，切换标签时内容淡入，不会因为技能少而缩窗口。

## 兼容性与已知冲突

**暂未发现冲突插件。** 本插件只注册一个输入框控件，并且只写入它报告的技能根。它仍可能与以下类型的插件冲突：

- **其他输入框槽位插件**：同样注册到 `conversation.input.left` 且 id/order 冲突，或替换整个工具条 → 按钮重复/布局重叠。
- **其他技能管理插件**：同样写入、移动、重命名或删除 `$DSH_HOME/skills`、`$DSH_AGENTS_HOME/skills`、`<projectRoot>/.dsh/skills`、`<projectRoot>/.agents/skills` 下的文件 → 跨插件写入没有锁；内容哈希只能拒绝外部修改后的保存，不能协调并发移动。
- **提供自定义 `skills` provider 或不同目录的插件**：这些技能在这里显示为只读/内置；同名技能可能遮蔽或重复文件系统里的技能。
- **替换或遮蔽 `skill` 工具 / 系统提示技能目录的插件**：面板列出的技能可能模型工具加载不到，反之亦然。
- **在输入框挂 document 级拖放/文件粘贴的插件**：导入表单打开时本插件会捕获面板上的拖放；其他 dropzone 可能争抢同一手势。导入表单之外不拦截拖放。
- **重写 `SKILL.md` frontmatter/标签但不保留 `managed-by`**，或重写块标量 `name` 的插件 → 来源标签或保存可能被对方拒绝/改写。
- **全局拦截 `Escape` 或键盘快捷键**、或把浮层 portal 到输入框上方的插件 → 焦点、Escape、z-index 可能冲突；本插件只在面板打开时监听。
- **主题/CSS 插件**覆盖弹层背景、`backdrop-filter` 或 z-index → 仅视觉冲突，不是数据冲突。
- **本插件的另一份副本**以不同包名/行 id 安装但指向同一批技能根 → 两个面板可编辑同一文件；建议只启用一份。

## 隐私

本仓库的意图是只包含插件源码、文档和一个原创图标；代码里不保存凭据或 API Key。

插件只读取配置的 DSH 主目录、工作区项目根目录下的技能文件，以及你主动提供的地址；不收集、不上传遥测。

首次公开提交前，请检查暂存文件和你的 git 身份：文档仍可能提到 `$DSH_HOME` 这类本地路径变量，提交记录也会带上本机配置的作者姓名/邮箱。这份 README 不构成“以后每次改动都不会出现敏感数据”的绝对保证。

## 限制

- **工作区作用域由同一工作区的所有会话共享**；“当前工作区会话”是项目技能根，不是单会话隔离。严格单会话隔离尚未实现。
- **内置技能和未知 provider 技能只读**：没有编辑、删除或标签操作。
- **导入只复制 `SKILL.md`**：拖入文件夹里的 `references/`、`scripts/` 等不会一起复制；地址导入只读取一个文件。
- **地址导入需要直接文件或受支持的 GitHub/Gitee 地址形式**：如果仓库根没有 `SKILL.md`，或 tree 路径没有指向技能目录，就无法解析。
- **YAML 支持是保守子集**：未闭合引号、未平衡的流式括号、制表符缩进会被拒绝；块标量 `name`/`tags` 的重写会被拒绝；块标量 description 保留；没有完整 YAML 解析器。
- **没有完整事务或撤销**：写入使用临时文件和尽力回滚，但移动与写入之间崩溃仍可能留下可恢复的中间状态。
- **包含一组聚焦 Host 的辅助函数测试**：`npm test` 运行 `test/host.test.mjs`；`npm run check` 对两个半边做语法检查。尚未提供浏览器端到端测试或 CI 工作流。
- 写入后会轮询 `skills/list` 等待文件监听器刷新。
- 保存会在会话日志里追加正常的 `/skill-hub` 命令生命周期记录；命令负载本身不会记录。只读的 `roots` 调用也会在每个面板会话中出现一次命令记录。
